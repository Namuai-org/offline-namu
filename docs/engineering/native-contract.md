# Namu native service contract

Status: implementation baseline for Android (Kotlin) and iOS (Swift). This
document refines PRD sections 3, 7, 8, 16 and 17 into one platform-neutral
contract. Where this document and the PRD differ, the PRD wins and this file
must be amended.

The TypeScript side of each interface is the codegen spec in
`src/infrastructure/platform/specs/`. Structured values cross the bridge as
JSON strings; the typed adapters in `src/infrastructure/platform/` validate
them. All byte counts are JSON numbers (exact integers below 2^53).

## 1. Build configuration (not secrets)

| Name | Android | iOS |
|---|---|---|
| `MODEL_ORIGIN` | `BuildConfig.MODEL_ORIGIN` | Info.plist `NamuModelOrigin` |
| Verification keys | `assets/namu/release-keys.json` | bundle `release-keys.json` |
| Bundled descriptor | `assets/namu/initial-descriptor.json` | bundle `initial-descriptor.json` |
| Bundled known-bad list | `assets/namu/known-bad.json` | bundle `known-bad.json` |
| Runtime build ID | `BuildConfig.RUNTIME_BUILD_ID` | Info.plist `NamuRuntimeBuildId` |
| Understood prompt versions | `["namu-text-1"]` constant | same |
| Bundled licence notice IDs | `["tiny-aya-cc-by-nc-4.0-v1"]` constant | same |

`MODEL_ORIGIN` is `https://<distribution-domain>` with no trailing slash.
Release builds MUST refuse a non-HTTPS origin. Internal (`.internal`) debug
builds may use `http://localhost` / `http://10.0.2.2` for the fault server.

`release-keys.json`: `{"keys":[{"key_id":"…","public_key_b64":"<32 raw bytes>"}]}`.
`known-bad.json`: `{"sha256":["<hex>", …]}`.

The repository ships **development** values of these three files generated by
`model-release/dev/` (a development key, never a production key). Production
values are produced by the release runbook and injected at build time.

## 2. Platform module (`NamuPlatform`)

`getDeviceProfile()` JSON:

```json
{
  "physicalMemoryBytes": 5900000000,
  "logicalCpuCount": 8,
  "freeDiskBytes": 31000000000,
  "osSupported": true,
  "abiSupported": true,
  "metalSupported": true,
  "thermalApiAvailable": true
}
```

* `physicalMemoryBytes`: Android `ActivityManager.MemoryInfo.totalMem`; iOS
  `ProcessInfo.physicalMemory`.
* `abiSupported`: Android `Build.SUPPORTED_64_BIT_ABIS` contains `arm64-v8a`
  (internal builds on an emulator also accept `x86_64`); iOS always true on
  arm64 devices.
* `metalSupported`: iOS `MTLCreateSystemDefaultDevice() != nil`; Android always
  `false` (CPU backend, DEV-004).
* Thermal mapping. Android `PowerManager` status: NONE→`nominal`,
  LIGHT/MODERATE→`fair`, SEVERE→`serious`, CRITICAL/EMERGENCY/SHUTDOWN→
  `critical`; API < 29 or unsupported → `unknown`. iOS
  `ProcessInfo.thermalState` maps one to one. Use the listener / notification;
  never poll headroom faster than platform guidance (INF-008).
* Memory pressure. Android `onTrimMemory` ≥ `RUNNING_LOW` → `warning`,
  `RUNNING_CRITICAL`/`COMPLETE` → `critical`. iOS
  `didReceiveMemoryWarning` → `critical`. Events MUST be delivered while no
  React screen is mounted (INF-007): emit from the module, not from a view.
* `prepareChatDataDirectory()`: Android `noBackupFilesDir/namu-data`; iOS
  `Library/Application Support/NamuData` with `isExcludedFromBackup = true`
  and `FileProtectionType.complete` on the directory (SEC-001).
* App-switcher privacy (SEC-007) is native-only: Android `FLAG_SECURE` on the
  main activity; iOS an opaque cover view between `willResignActive` and
  `didBecomeActive`.

## 3. Storage layout (DL-008)

Root: Android `noBackupFilesDir/namu-models`; iOS
`Library/Application Support/NamuModels` (backup-excluded, protection
`completeUntilFirstUserAuthentication` so background transfers can finish).

```
<root>/journal/transfer-journal.sqlite      native journal (+ -wal, -shm)
<root>/staging/<transferId>.part            Android partial file
<root>/staging/<transferId>.download        iOS moved completed temp file
<root>/releases/<sha256>/model.gguf         verified immutable release (0444)
<root>/active.json                          activation authority (DL-012)
<root>/pending-activation.json              marker written before self-test
```

Artifact ID = lowercase SHA-256 hex from the signed descriptor (validated
`^[0-9a-f]{64}$`). Transfer ID = app-generated UUIDv4. No path component is
ever taken from a server response or from user input.

## 4. Signed descriptor (SIG-001…005)

Envelope: `{"key_id": "...", "payload_b64": "...", "signature_b64": "..."}`.
Standard base64 with padding. Limits: envelope ≤ 65,536 bytes, decoded payload
≤ 32,768 bytes, signature exactly 64 bytes.

Verification order — any failure is `SIGNATURE_INVALID` unless noted:

1. Size limits. Strict JSON parse of the envelope (see 4.1).
2. `key_id` selects a bundled key; unknown key → reject.
3. Ed25519 verify `signature` over the **decoded payload bytes**
   (Tink `Ed25519Verify` / CryptoKit `Curve25519.Signing.PublicKey`).
4. Only now parse the payload with the strict parser. Payload must be UTF-8.
5. Field validation (table below). Compatibility failures are
   `MODEL_INCOMPATIBLE`.
6. Sequence rule against the journal: `sequence < highest` → reject;
   `sequence == highest` and payload SHA-256 differs → reject; otherwise accept
   and persist `(sequence, payload_sha256)` when `sequence > highest`.
   The bundled descriptor does not advance or consult the stored sequence.
7. Remote descriptors: `issued_at ≤ now + 24 h` and `now < expires_at`, and
   `expires_at − issued_at ≤ 180 days`. The bundled descriptor is exempt from
   expiry for its exact digest (SIG-004).
8. `sha256` must not be in the bundled or local known-bad list, else
   `FILE_DAMAGED`.

Conformance: `model-release/test-vectors/descriptor-vectors.json` holds
`keys`, a default `context` (`appBuild`, `runtimeBuildId`, `promptVersions`,
`licenseNoticeIds`, `now`, `highestSequence`,
`highestSequencePayloadSha256`, `knownBad`) and `vectors[]` of
`{name, source, context (overrides), envelope_b64, expect}` where `expect` is
`accept` or the rejection code. The reference implementation is
`model-release/descriptor/verify.mjs`.

| Field | Rule |
|---|---|
| `schema` | integer `1` |
| `sequence` | integer ≥ 1 |
| `model_id` | `"namu-aya-global"` |
| `artifact_version` | string `^[A-Za-z0-9._-]{1,64}$` |
| `path` | `^[A-Za-z0-9._/-]{1,512}$`, no leading `/`, no `//`, no `.`/`..` segment |
| `bytes` | integer, 1 … 8,000,000,000 |
| `sha256` | `^[0-9a-f]{64}$` |
| `upstream_repo`, `upstream_revision`, `upstream_filename` | non-empty strings; revision `^[0-9a-f]{40}$` |
| `architecture`, `quantization` | `"cohere2"`, `"Q4_K_M"` |
| `runtime_build_ids` | array of strings containing this app's runtime build ID, else `MODEL_INCOMPATIBLE` |
| `min_app_build`, `max_app_build` | integers, `min ≤ appBuild ≤ max`, else `MODEL_INCOMPATIBLE` |
| `prompt_version` | in understood list, else `MODEL_INCOMPATIBLE` |
| `license_notice_id` | in bundled list, else `MODEL_INCOMPATIBLE` |
| `issued_at`, `expires_at` | RFC 3339 UTC, `YYYY-MM-DDTHH:MM:SSZ` |

Internal (`.internal`) builds additionally accept the development fixture
profile `architecture ∈ {cohere2, llama}` and
`quantization ∈ {Q4_K_M, Q8_0, F16, F32}` so a small redistributable fixture
GGUF can exercise the pipeline (REL-001). Release builds accept only
`cohere2` / `Q4_K_M`, and refuse to build with a verification key whose
`key_id` starts with `dev-`.

Artifact URL = `MODEL_ORIGIN + "/" + path`. Update descriptor URL =
`MODEL_ORIGIN + "/releases/stable.json"`. Redirects to another origin are
rejected (DL-003).

### 4.1 Strict JSON

Both platforms implement the same small recursive-descent parser: RFC 8259
grammar, UTF-8 only, maximum depth 16, **duplicate object keys at any depth
are an error**, integers must be exact (no fraction/exponent for integer
fields), no trailing data. Platform JSON libraries that silently keep the last
duplicate MUST NOT be used for descriptors. Shared vectors live in
`model-release/test-vectors/` and are consumed by the Kotlin, Swift, Python
and Jest tests.

## 5. Transfer journal (DL-002)

SQLite, WAL, `synchronous=FULL`, owned only by the native service.

```sql
CREATE TABLE transfers (
  transfer_id TEXT PRIMARY KEY,
  descriptor_source TEXT NOT NULL,          -- 'bundled' | 'update'
  descriptor_bytes BLOB NOT NULL,           -- verified envelope
  descriptor_hash TEXT NOT NULL,            -- sha256 of payload bytes
  artifact_version TEXT NOT NULL,
  artifact_sha256 TEXT NOT NULL UNIQUE,     -- one transfer per artifact
  artifact_path TEXT NOT NULL,
  phase TEXT NOT NULL,
  expected_bytes INTEGER NOT NULL,
  committed_bytes INTEGER NOT NULL DEFAULT 0,
  verified_bytes INTEGER NOT NULL DEFAULT 0,
  etag TEXT,
  staged_filename TEXT,
  os_task_id TEXT,
  resume_data BLOB,                         -- iOS opaque resume data
  metered_consent INTEGER NOT NULL DEFAULT 0,
  user_paused INTEGER NOT NULL DEFAULT 0,
  restarted_from_zero INTEGER NOT NULL DEFAULT 0,
  retry_count INTEGER NOT NULL DEFAULT 0,
  next_retry_at INTEGER,
  last_error TEXT,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
CREATE TABLE meta (key TEXT PRIMARY KEY, value TEXT NOT NULL);
CREATE TABLE bad_digests (sha256 TEXT PRIMARY KEY, reason TEXT NOT NULL, marked_at INTEGER NOT NULL);
```

`meta` keys: `highest_sequence`, `highest_sequence_payload_sha256`,
`active_mirror` (JSON copy of active.json), `update_descriptor` (latest
verified update envelope, base64), `journal_schema`.

Phases (DL-015): `absent, waiting, downloading, paused, verifying, staged,
selfTesting, installed, failed, removing`. `waiting` carries a reason in
`last_error`: `NETWORK_WAIT`, `SPACE_LOW` or a retry back-off.

## 6. Transfer protocol

### 6.1 Common rules

* Space (DL-009): before start/resume require
  `free ≥ (B − P) + 1 GiB`. While transferring, pause with `SPACE_LOW` when
  free space falls below 256 MiB. Recheck before verification output and
  before activation. iOS adds `B` again when the completed temp file cannot be
  moved on the same volume.
* Network policy (DL-006): unmetered only unless `metered_consent = 1` for
  this transfer. Consent is per transfer and never inherited by an update.
  Loss of network → `waiting/NETWORK_WAIT`, not failure. `user_paused`
  persists until `resume`.
* Retry (DL-007): transient I/O, 408, 429, 5xx → back-off 2, 5, 15, 30, 60 s
  with up to +20 % jitter; honour `Retry-After` up to 15 min. After five
  consecutive failures → `failed/TRANSFER_RETRY` (user retry required).
  Progress resets the counter. Other 4xx, signature, hash and compatibility
  errors never auto-retry.
* Never accept more than `expected_bytes`; abort the body at the bound (T07).
* Snapshots to JS are coalesced to ≥ 250 ms apart; phase changes flush
  immediately.

### 6.2 Android HTTP rules (DL-003, DL-004)

OkHttp client: no transparent gzip (`Accept-Encoding: identity` set
explicitly), `followRedirects(false)` with manual same-origin redirect
handling (max 3), no cache, no cookies.

| Situation | Behaviour |
|---|---|
| Fresh GET | expect `200`; `Content-Length`, if present, must equal `B`; store strong `ETag` |
| Resume | `Range: bytes=P-` and `If-Range: <strong etag>`; without a strong ETag restart from zero |
| `206` | require `Content-Range: bytes P-(B-1)/B` exactly and same ETag (if sent); else discard response, truncate and restart |
| `200` on resume | truncate `.part` to 0, `restarted_from_zero = 1`, process as fresh |
| `416` | if local length == `B` go to verifying; else truncate and restart |
| Body shorter than promised | keep durable bytes, retry per 6.1 |
| Body longer than `B` | abort, delete staging, `failed/FILE_DAMAGED` |
| `Content-Encoding` other than identity | reject |

Durability: write to `.part`; every 4 MiB or 2 s (whichever first) and on
graceful stop `fsync` the file **then** journal `committed_bytes`. On restart
truncate the file to `committed_bytes` before resuming. Hash state is never
serialized; the whole file is rehashed after download.

Execution: API 34+ user-initiated data transfer `JobService`
(`setUserInitiated(true)`, network constraint from consent, notification);
API 29–33 `CoroutineWorker` promoted to foreground (`dataSync`). Both call the
same `TransferEngine` and run with no JS runtime (ARC-003).

### 6.3 iOS rules (DL-005)

One background `URLSession`, identifier `<bundleId>.model-transfer`,
`isDiscretionary = false`, `sessionSendsLaunchEvents = true`,
`allowsCellularAccess`/`allowsExpensiveNetworkAccess` from consent, serial
delegate queue. Persist `taskIdentifier` and opaque resume data. On launch call
`getAllTasks` and reconcile with the journal. In
`urlSession(_:downloadTask:didFinishDownloadingTo:)` validate the HTTP status
and move the temp file into `<root>/staging` **inside the callback**. If resume
data is missing or rejected, restart from zero and set
`restarted_from_zero = 1` so the UI can say so (`TRANSFER_RESTART`). Never
promise continuation after a user force-quit (T12).
`application(_:handleEventsForBackgroundURLSession:completionHandler:)` stores
and later invokes the completion handler.

### 6.4 Verification and installation (DL-010)

1. Exact length == `bytes`, else `FILE_DAMAGED`.
2. Streaming SHA-256 (8 MiB buffer), publishing `verified_bytes` for the UI.
   Mismatch → delete staging only, `failed/FILE_DAMAGED`.
3. Structural GGUF check **after** the hash passes and without the native
   inference parser: magic `GGUF`, version 2 or 3, tensor count and metadata
   count within sane bounds (≤ 65,536 and ≤ 4,096), bounded walk of the
   metadata key/value section to find `general.architecture`; it must equal the
   descriptor's `architecture`. Any bound violation → `FILE_DAMAGED`;
   architecture mismatch → `MODEL_INCOMPATIBLE`.
4. `mkdir releases/<sha256>`, rename staging file to `model.gguf` (same
   volume), chmod read-only, fsync directory. Phase `staged`.
5. `beginSelfTest`: write `pending-activation.json`
   `{transferId, artifactId, startedAt}` durably, phase `selfTesting`.
6. `activate(pass=true)`: recheck space, write `active.json.tmp`, fsync,
   atomic rename over `active.json`, fsync directory, mirror into the journal,
   phase `installed`, delete the marker.
   `activate(pass=false)`: add digest to `bad_digests`, delete the candidate
   release, delete the marker, phase `failed` with the supplied code; the old
   pointer is untouched.

`active.json`:

```json
{
  "schema": 1,
  "active": {"artifactId": "<sha256>", "version": "…", "bytes": 0, "sha256": "…", "activatedAt": 0},
  "previous": null,
  "trial": {"startedAt": 0, "successfulSessions": 0}
}
```

Startup reconciliation (DL-012, DL-014), before answering the first snapshot:

* marker present → the process died during self-test: quarantine the candidate
  (bad digest, delete release), delete marker, transfer `failed/MODEL_LOAD_FAILED`.
* pointer missing/corrupt but a `.tmp` exists → ignore `.tmp` (never promote).
* pointer valid: check `model.gguf` exists with exact length (no rehash).
  Anomaly → install state `needsRepair`.
* verified release without pointer → transfer stays `staged` (not installed).
* journal mirror is rewritten from the pointer.
* Android: truncate `.part` files to `committed_bytes`; iOS: reconcile tasks.

Retention (DL-013): keep `previous` until 7 days **and** three successful
foreground sessions have passed, then delete it when no runtime reference is
held. `restorePrevious` swaps the pointer atomically and marks the abandoned
digest bad only when invoked automatically after a failed trial.
`removeModel` and `deleteAllTransferData` reject with `ENGINE_BUSY` while a
runtime reference is set (SEC-006).

### 6.5 Snapshot JSON

```json
{
  "schema": 1,
  "install": {
    "state": "absent | installed | needsRepair",
    "active": {"artifactId": "…", "version": "…", "bytes": 0, "sha256": "…", "activatedAt": 0},
    "previous": null,
    "canRestorePrevious": false
  },
  "transfer": {
    "transferId": "…", "isUpdate": false,
    "artifactVersion": "…", "artifactSha256": "…",
    "phase": "downloading",
    "expectedBytes": 0, "committedBytes": 0, "verifiedBytes": 0,
    "meteredConsent": false, "userPaused": false,
    "restartedFromZero": false, "retryCount": 0,
    "nextRetryAt": null, "errorCode": null
  },
  "update": {"artifactVersion": "…", "bytes": 0, "sequence": 0},
  "network": {"connected": true, "metered": false},
  "storage": {"freeBytes": 0, "requiredAdditionalBytes": 0}
}
```

`transfer` and `update` may be `null`. `errorCode` uses the PRD section 17
codes only. `getBundledDescriptorSummary()` →
`{"valid": true, "artifactVersion": "…", "bytes": 0, "sha256": "…", "errorCode": null}`.
`checkForUpdate()` → `{"status": "none | available | error", "errorCode": null}`.

Promise rejections use the `code` field with one of: PRD section 17 codes,
`ENGINE_BUSY`, `NOT_FOUND`, `INVALID_STATE`.

## 7. Export module (SEC-004, SEC-005)

Exports directory: Android `cacheDir/namu-exports` (shared through a
`FileProvider` with a single `exports` path); iOS
`Library/Caches/NamuExports` (backup-excluded).

Single conversation: `<export-id>/<safe-title>.txt`, UTF-8 without BOM, `\n`
newlines:

```
<title>
<labels.created>: <ISO 8601 UTC>
<labels.updated>: <ISO 8601 UTC>
<labels.responseLanguage>: <labels.languageNames[code]>

<labels.you>:
<user text>

<labels.namu>:
<selected attempt content>
[<labels.interrupted>]        only when status is interrupted/stopped/failed
[<labels.lengthLimited>]      only when finish_reason = 'length'
```

`safe-title` = title with every character outside letters/digits/space/`-_`
replaced by `_`, trimmed to 60 UTF-16 units, fallback `conversation`.
Turns stream in `ordinal` order with `LIMIT 200` pages inside **one** read
transaction. Only the selected attempt is exported; a turn with no selected
attempt exports the user text alone.

All conversations: `namu-export-<yyyyMMdd-HHmmss>.zip` containing
`conversations/<n>-<safe-title>.txt` and `index.json`:

```json
{"export_schema": 1, "exported_at": "…Z", "app_version": "…",
 "conversations": [{"id": "…", "title": "…", "file": "conversations/1-….txt",
                    "created_at": "…Z", "updated_at": "…Z", "turns": 0}]}
```

`share` presents the system sheet only after the file is complete. Failure or
low space removes the partial export and leaves the database untouched (T23).
`sweepExports` deletes entries older than 24 h and is called on every start.
